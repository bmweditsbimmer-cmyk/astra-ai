# Astra AI — Public Deployment ZIP

A responsive starter website with AI chat UI, browser text-to-speech, speech input where supported, an astrology information section, example subscription plans, and a server-side AI API proxy with a separate owner login.

## Quick local setup (Windows)
1. Install Node.js 20 or newer.
2. Extract this ZIP and open PowerShell in the `astra-ai` folder.
3. Run `npm install`.
4. Copy `.env.example` to `.env`.
5. Edit `.env`: set a long random `SESSION_SECRET`, `OWNER_USERNAME`, `OWNER_PASSWORD`, and your provider's `AI_API_KEY`.
6. Run `npm start`.
7. Open `http://localhost:3000`.

Never share or commit `.env`. Do not paste API keys into chat or browser code.

## Publish publicly on Render
1. Create/sign in to GitHub and create a **private** repository named `astra-ai`.
2. Extract this ZIP and upload the contents of the `astra-ai` folder to that repository. Do **not** upload `.env` or any API key.
3. Sign in at https://render.com/ and choose **New → Blueprint** (or create a Web Service from the repo).
4. Select the GitHub repository containing `render.yaml`. Render will read the deployment configuration.
5. In the Render environment-variable prompt/dashboard, set `OWNER_PASSWORD` to a strong, unique password and `AI_API_KEY` to your own provider API key. Keep `SESSION_SECRET` generated by Render. Never use the example owner password on a public site.
6. Deploy. When the deployment succeeds, Render shows a public `*.onrender.com` URL. Open it to test the site.

If the ZIP is uploaded as a file, Render cannot deploy the ZIP directly by itself; the source must first be placed in a Git repository or another supported deployment source. Do not publish this as a static-only site (for example, GitHub Pages), because `/api/chat` and `/api/status` require the Node.js backend. If chat says “Unable to connect”, open `https://YOUR-SITE/api/status`: a working deployment returns JSON. If that URL shows a 404 or HTML page, deploy this project as a Node.js Web Service using `npm install` and `npm start`, and check the hosting logs. The exact Render dashboard labels may change.

## AI provider settings
This server uses an OpenAI-compatible `/chat/completions` API. Set `AI_BASE_URL`, `AI_MODEL`, and `AI_API_KEY` for your chosen provider. Without a valid key, chat will show a configuration error rather than inventing an AI answer.

## Owner login
Open **Owner dashboard** in the website. Default username is `owner`; the password is the server environment variable `OWNER_PASSWORD`. Owner credentials are never embedded in frontend JavaScript. Set the password in your hosting dashboard before publishing.

## Important before real public launch
- This is a deployable starter, not a complete commercial SaaS.
- Plans/prices are illustrative only. Payments, customer accounts, persistent plan editing, usage quotas and billing are not implemented.
- Astrology is informational/traditional. This app does not calculate verified natal charts, current planetary positions or real-time panchang; connect a reliable chart/ephemeris service for those features.
- Browser voice features depend on browser/device support. Uploaded files are not processed by the AI in this starter.
- Chat history is stored in browser local storage, not synced to accounts.
- The default session store is in-memory. For a production service with multiple instances, configure a persistent session store and database, review privacy/security, and test rate limits.
- HTTPS, privacy policy, terms, abuse controls, monitoring and backups should be configured before inviting the public.
